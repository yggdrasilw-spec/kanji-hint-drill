# 縦書きUIの設計資料（2026-10-18）

## 調べた一次資料
- W3C 日本語組版処理の要件 https://www.w3.org/TR/jlreq/
- W3C CSS Writing Modes Level 3 https://www.w3.org/TR/css-writing-modes-3/
- W3C Styling vertical Chinese, Japanese, Korean and Mongolian text https://www.w3.org/International/articles/vertical-text/

資料が定めるのは文字組みであり、子ども向けボタンや利き手の配置の最適解ではない。以下はこのアプリの設計判断。

## 方針
日本語は上から下、列は右から左（vertical-rl）。句読点・長音の縦組み字形を使うため本文はmixed。短い操作名は途中で折り返さず一列にする。説明は高さを区切って列を送る。物理的な幅・高さと論理的なinline/block寸法を混ぜた上書きを重ねない。

小さい選択肢集合は縦書きの選択ボタンを使う。ネイティブselectのoptionはブラウザによって横書きになるため、共通設定では同じselectの値を更新するボタンを用意する。多数の漢字を選ぶ先生用selectとファイルダイアログはOSの選択機能を残す。描画面・図・配置用コンテナは文字の流れから独立させる。

右手では練習枠を問題文の右側、左手では左側に置き、補助パネルも反対側に移す。ヘッダーの一操作で切替・保存。切替ではDOMのcanvasを作り直さず筆跡・出題・記録を保持する。狭い画面でも問題と練習枠を左右に置く。

## 始点・終点
手本の位置は正しい字の唯一の位置ではない。従来の許容幅（ゆるめ14%、標準10%、厳しめ6.5%）を基準に、１〜２画1.8倍、３〜４画1.5倍、５〜６画1.25倍、７画以上1倍とする。位置の助言は紫色で、誤答の修正表示と区別する。線の過不足・字を区別する長短等は従来どおり独立して確認する。これは暫定の設計値であり、児童の実筆跡に基づく校正値ではない。

## 確認
右左切替時の筆跡・保存、再読込、縦書きの短いボタンの一列表示、設定・漢字選択・開始・読み・記録の操作、320/390/768/1366幅、少画数の許容と大きな逸脱の検出を検証する。

## 交差の確認（2026-10-18追記）
手本と突出の長さをそろえる判定を交差確認から外した。「土」の縦線上部を15〜35%短くしても交差する例で、旧判定は交差距離0でもfailになった。現在は実筆跡の交点の有無を優先し、字全体100に対して交点と端の距離がゆるめ1.5・標準2.5・厳しめ4以上なら交差を確認する（手本の突出自体が短い場合は基準を下げる）。端ぎりぎりなら「交差していますが端に近い」、小さな隙間は自己確認、離れた線は「離れて見える」と具体的に説明する。字を区別する突出・長短や任意の美文字助言は独立して残す。これらも実筆跡校正済みの閾値ではない。
