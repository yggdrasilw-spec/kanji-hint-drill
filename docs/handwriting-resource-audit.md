## 結論

部品の画範囲、位置、異体形、名前、SVGの色付け、レビューの方法を再利用できる。
長さ・比率の判定器や正しい数値は既存データにはなく、今回の共通エンジンで追加する。
部首クイズの正解データを、すべての構成部品の分解や字形判定の正解と同一視しない。

## 実ファイルの機械照合

本アプリの1,026字からUnicodeを5桁の小文字16進に変換し、部品JSON・元SVGを照合した。
SVGのpath順とd文字列を、本アプリの全paths配列と比較した。
部品のrangesが画配列内の整数・両端を含む区間か、どの画が所属するかを数えた。
結果とSHA-256は[機械照合結果](handwriting-resource-audit.json)に保存した。

| 検査 | 結果 | 解釈 |
|---|---|---|
| 本アプリの対象字 | 1,026字 | 全配当字を比較 |
| kanji_partsのキー | 1,026件 | 本アプリ対象で部品項目がない字は0 |
| 元SVGと本アプリのパス列 | 1,026字すべて一致 | このスナップショットでは画の添字を対応させられる |
| 範囲外・逆転・整数でないranges | 0件 | 添字上の範囲は有効 |
| 非連続なrangesを持つ部品 | 35件 | start～endで平らにしてはいけない |
| どの部品にも所属しない画 | 弱 | 6～8画目に相当する範囲が部品一覧から欠ける。取り込み時に元SVGで補完 |
| 部品間の重複所属 | 老・興 | 全体部品・部分部品や部首向け上書きが重なる。別の画として複製しない |
| 辞書部首の照合 | matched 1,024、candidate集計2 | 手書き答案や字形の正しさを検証した値ではない |
| 辞書照合の要レビュー | 母・表 | reportのstatusはreview。元アプリの未解決状態を維持して移行 |

重複所属は必ずしも誤データではない。階層として保持するか、明示的な選択・補完が必要。
部品の件数と、すべての画を重複なく分割できる字数を混同しない。
今回の一致検証は構造・文字列の検査であり、部品の呼び名や教材上の正誤を人手で承認したものではない。

## 具体的に役立つ対応と、補う対応

以下の画番号は、読みやすいよう1始まりに変換した値。

| 字 | 部品データにある対応 | 新しい判定に必要な補足 |
|---|---|---|
| 鉄 | 金＝1～8画、失＝9～13画 | 金偏の各線の役割、失の突出・境界の対象 |
| 知 | 矢＝1～5画、口＝6～8画 | 矢の偏形と終画の収まり、口との空隙 |
| 利 | 刂＝6～7画、禾＝1～5画 | 刂の左短縦・右長縦、右縦のはねの分離 |
| 地 | 土＝1～3画、也＝4～6画 | 土偏の払い上げと単独土の下横画の違い |
| 理 | 王＝1～4画、里＝5～11画 | 玉偏としての形のプロファイル。部品ラベルだけで意味上の部首を変更しない |
| 三 | 一＝1画、一・一＝2～3画 | 三本の個別役割と長短比較対を別に定義 |
| 見 | 字全体＝1～7画 | 元SVGの目＝1～5画・儿＝6～7画を取得。内部横線は3・4画 |
| 青 | 字全体＝1～8画 | 元SVGの上部龶＝1～4画・下部月＝5～8画を取得。上部横画と下部内側横画を分ける |
| 金・月 | 各字全体 | 主横画・側線・はねなどの役割を追加する |
| 明・服 | 日／月、月／右側の部品 | 月の右側・左側・肉由来の形を区別する情報を元SVGから補う |

服のSVGの左側は`element=月`、`original=肉`、`variant=true`。
名称の異体形照合で同じ「月」としたことを理由に、単独月の幅プロファイルを自動で適用しない。
青の下部を細めにする程度と、単独月・明の右側・服の左側の細さは、それぞれの配置に合わせてレビューする。

## 取り込みの手順

1. 元リポジトリの状態とファイルハッシュを読み、本監査のスナップショットから変更された資源を抽出する。
2. 対象字を本アプリのcurriculumから取り、5桁の小文字16進キーへ変換する。
3. rangesを優先して画の集合を作り、元SVGと本アプリのパス順・内容を再照合する。
4. 辞書部首のラベルと、字形検査に必要な部品階層・画の役割を分けて取り込む。
5. 全体部首・欠落・重複・非連続範囲を一覧化し、元SVGと明示的なレビュー修正で補完する。
6. 元部品の要素・位置・original・variant・rangesを保ち、自前の部品形と永続IDに対応させる。
7. 名称と形のプロファイルを別々にレビューし、未確認は未確認のまま保存する。
8. 本アプリ内へ生成し、出典・元ハッシュ・変換器の版・補完履歴をmanifestへ保存する。
9. 代表字の設定・焦点・長短・幅を検証し、更新で影響する全字を追跡できるようにする。

本アプリの実行時に、元アプリへネットワーク依存やローカルの絶対パス依存を追加しない。
元アプリのデータを同期上書きする仕組みは作らない。

## 出典と帰属

[部首ハンターのREADME](../../kakijun/bushu-hunter/README.md)は、直下部品候補の`kanjivg-radical`とKANJIDIC2由来データをCC BY-SA 4.0、元の筆順SVGをCC BY-SA 3.0として記している。
個別修正・辞書照合のURLもファイル内に残っている。
次の実装で使用するフィールドの元と変換を分け、既存の帰属とライセンスの記録を引き継ぐ。
部首画像や外部辞書の本文を再配布することは、この再利用方針の対象に含めない。
根拠を確かめるリンクと、アプリへ組み込む機械データを区別する。

本調査のデータが将来更新された場合は、現在の数値・対応を確認済みのまま引き継がず、再照合する。
