# 接触・はね・注意箇所の表示の修正

## 接触を必須にしない

従来の `topology` は、KanjiVGのお手本で近い線を自動抽出した規則であり、接触が文字の区別に必須かどうかを確認したものではありませんでした。それが「骨組み・線の過不足」の設定で動き、接触の項目をオフにしても自己確認を求めていました。

この自動抽出規則を任意の書き方の参考項目に移し、「線の接触（参考）」 (`structureContact`) を独立させました。初期値は「見ない」です。以前の保存設定にこのキーがない場合もオフを補完します。必要な線の過不足、囲み内の横線、字を区別する長短や突出の設定は独立して使えます。参考項目をオンにしても、文字認識が正しければ接触だけで誤答や自己確認にはせず、書き方の復習として扱います。

「鉄」の従来の接続設定と金偏の任意の接続設定は別項目です。接続を測る線が斜めでも評価できるよう、任意の接続検査から水平軸への依存を除きました。

## 「向」の3画目のはね

従来は画種を完全一致で比較し、`㇆a` を持つ「向」の3画目を対象にしていませんでした。画種の補助記号と複数候補を扱い、横折れはね、曲がりはね、心のはねなどの対象を補完します。既存の生成データを読んでも補完され、再生成にも同じ判定を適用します。

最後の固定12.5%で方向を測る方式では、小さなはねに縦線が混ざってしまいました。最後の1・2・3・5・8・12%の複数の区間を比較し、短い終端の向きの変化を拾います。ごく小さなノイズは長さで除きます。お手本に終端のはねを確認できない場合は検査不能として表示を省き、画種だけから必須にしません。角度の基準もお手本の変化量に応じて緩和します。

はねは引き続き任意の書き方の練習項目です。「見ない」と字別・規則別の調整を尊重します。筆圧、停止、筆を離す速度は測定していません。

## 指摘と強調表示を一致させる

接触の明確な問題だけでなく、許容幅の境界でも対象の二本の筆跡番号を返します。画の対応自体が曖昧で二本を特定できない場合は、「字全体を比べよう」という案内に切り替えます。

指摘一覧の初期選択は、対象が分かる指摘を優先します。選択ボタン、個別の説明、強調表示を同じ指摘に揃え、一覧を更新した時点で描画します。実行エンジンのバージョンは `component-engine-2` として記録します。

## 検証

Playwrightが利用できるNode環境で、`node scripts/serve.mjs` を起動してから `node tests/generate-reference-fixtures.cjs` で全字のお手本座標を生成します。生成物は既存の `qa/` に保存し、リポジトリには追加しません。サーバーのURLは `APP_URL`、Chromiumの実行ファイルは `CHROMIUM_PATH` で指定できます。

- `node tests/handwriting-feedback.test.mjs`: 「向」のはねの有無、オフと字別調整、小さなはね、斜めの接続、接触の境界と曖昧な対応、全字の769件のはね候補でお手本を誤って失敗にしないこと。
- `node tests/handwriting-feedback.cjs`: サーバーを自動起動。認識結果を「向」に固定し、3画目の指摘と強調表示、二本の選択と切替、設定の初期値、320〜1280pxの設定画面を検証。
- 既存の `tests/shape-expansion.test.mjs`、`tests/shape-settings.test.mjs`、`tests/shape-focus.test.mjs`、`tests/core.test.mjs` で骨組み、設定、丸、記録への回帰を確認。

これらは合成筆跡による機能検証です。実筆跡による許容幅の校正や実モデルの認識精度の測定は含みません。
